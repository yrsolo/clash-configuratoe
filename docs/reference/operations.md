# Обслуживание, ограничения и диагностика

## Резервные копии

Перед существенным изменением скачайте JSON через экспорт редактора. Он сохраняет холст и редактируемую схему; YAML не заменяет такую копию. **Экспорт не обезличивается автоматически**: храните файл приватно. Для облачного workspace сохраняйте резервную копию всего закрытого бакета, включая index, проекты, публикации и secrets. `secrets.json` — отдельный объект, не криптографическая защита.

Сохраните вне Git Folder ID, ID функции/Gateway/двух сервисных аккаунтов, имена бакетов, build-настройки с публичной солью, список версий функции и копию последнего `apps/web/dist`. Выдавать весь облачный аккаунт новому владельцу не нужно: обычная передача предполагает самостоятельное развёртывание.

Не меняйте `VITE_WORKSPACE_APP_SALT` при обычных релизах: вместе с именем и кодом она участвует в хеше доступа. После изменения человек увидит другое workspace. Потерянный код не восстанавливается через email; у MVP нет такой функции.

## Ссылки и секреты

YAML URL и share URL содержат токен; получивший его может читать конфигурацию и связанные реквизиты. Не публикуйте URL, QR, JSON/YAML, логи с query-параметрами и `secrets.json`. Администраторы бакета/функции имеют доступ к данным. Соль публичная и не превращает слабый код доступа в сильный пароль.

Для workspace API клиент передаёт `userKey`, который является доступом к его данным; сервер не проверяет отдельный пароль. Используйте длинный случайный код, доверенные устройства и HTTPS. Публичные операции публикации/formatter пока не имеют полноценного управления владельцами, rate limiting и строгого списка допустимых upstream-адресов. До широкого публичного использования нужны серверная аутентификация, контроль записи, ограничения исходящих запросов и защита от расходов/злоупотреблений. MVP для личной установки не следует представлять как защищённый SaaS.

## Ротация

Ссылки и учётные данные, попавшие в историю Git или чужой архив, надо перевыпустить у провайдера; замена строк в последнем коммите не отзывает старые. Локальный корневой `.env`, если он есть у предыдущего владельца, считайте скомпрометированным материалом и не используйте на новой установке.

Для S3 создайте новый ключ своего runtime-аккаунта, обновите переменные, создайте новую версию функции, проверьте сохранение/чтение и только затем отзовите старый ключ в IAM. Помните, что старые версии функции также содержат прежнее окружение; откат на них после отзыва ключа потребует обновления. `yc iam access-key delete` принимает ID ключа (`access_key.id`), не его `key_id`. См. [управление ключами](https://yandex.cloud/ru/docs/iam/operations/authentication/manage-access-keys).

Для отзыва ссылки workspace можно удалить проект в редакторе: API удаления удаляет связанную стабильную публикацию. Сначала сохраните JSON, затем при необходимости импортируйте его как **новый** проект и настройте заново. Смена/выход из кода доступа сама по себе старую публикацию не отзывает. Гостевой snapshot не связан с удалением workspace-проекта; его отзыв требует административного удаления соответствующего объекта публикации в приватном бакете.

## Обновления и откат

Для обновления выполните [повторный деплой](yandex-deploy.md), сохранив домен, публичную соль и IDs. После каждой версии проверьте сохранение workspace и опубликованный YAML. Gateway указывает на `$latest`, поэтому новая версия функции применяется сразу.

При проблеме функции откройте Cloud Functions → функция → версии, найдите известную рабочую версию. Надёжный вариант отката — в копии `deploy/yandex/gateway.local.yaml` заменить `tag: $latest` на **свой release tag**, назначенный рабочей версии через консоль, и обновить Gateway этим файлом. Проверьте все function integrations, а не один route. Не пытайтесь назначать зарезервированный `$latest` вручную. Возврат к обновлению по `$latest` делайте осознанно после проверки новой версии.

Frontend откатывается загрузкой сохранённого `dist`: сначала его assets, затем `index.html`. Не удаляйте новые/старые assets до завершения проверки. Изменение ID проекта, домена или соли затрагивает пользовательские ссылки/доступ, поэтому не используйте его как обычный откат.

## Проверка зависимостей

После установки проверяйте обе независимые группы пакетов:

```bash
npm audit
npm audit --prefix serverless/workspace-bridge
```

При подготовке 7 октября 2026 года обновлены lock-файлы, Vitest до 4.1.11 и undici до 7.30.0; обе проверки завершились без известных npm уязвимостей. Это результат на дату проверки, а не гарантия защищённости приложения. Не запускайте `npm audit fix --force` без разбора изменений: обновления могут потребовать новую основную версию. После обновления выполните `npm run release-check` и проверку деплоя.

## Где искать ошибку

| Симптом | Проверка | Действие |
| --- | --- | --- |
| Локально сохранение/публикация выдаёт 404 | Vite не реализует `/api/*` | Используйте развёрнутый Gateway; локальная правка/экспорт работают отдельно |
| Белый экран, assets возвращают HTML | Network, MIME, ключи объектов | Перезагрузите корректный `dist`, проверьте путь `/assets/{path+}` и права gateway на frontend |
| Gateway 403/500 на API | Function ID, invoker binding, payload 2.0 | Сверьте spec и `functions.functionInvoker` для gateway account |
| Ошибка S3 AccessDenied/NoSuchBucket | Runtime env, роль на workspace, существование бакета | Проверьте **свои** bucket/key_id/secret и область роли; не делайте бакет публичным |
| Подписка возвращает HTML/401/403 | Формат ответа, токен, активность подписки | Возьмите реальный feed URL; выберите native Clash или поддерживаемый legacy формат |
| Timeout подписки из облака | Прямой доступ из функции, доступность HTTP(S)/SOCKS5 proxy | Исправьте `PROXY_URL` при необходимости; проверьте установку зависимостей по актуальному lock-файлу |
| Native YAML сохраняется, но сервер не подключается | Протокол/транспорт, версия ядра, server/порт | Проверяйте на целевом клиенте; inspector не доказывает поддержку транспорта этим клиентом |
| Группа пуста или только DIRECT | Выключенный source, связи, filter terms | Включите свой источник, поправьте названия фильтров и маршрут Merge |
| Нет изменений в клиенте | Workspace или guest snapshot, Refresh publish, Update профиля | Выполните оба обновления, сверяйте именно YAML URL |
| API возвращает старые серверы | Ошибка upstream, cache | Явный refresh показывает ошибку; обычное чтение может вернуть предыдущий cached YAML при неудаче обновления |
| Run probe не работает | Linux binary, размер пакета, лог функции | Проверьте `bin/sing-box`; это отдельный механизм от скачивания/экспорта |
| Проект «пропал» | Имя/код/соль, origin localStorage | Восстановите прежние значения; другая идентичность не видит старые данные |
| Сервис открывается напрямую | Rule mode, выбранный DIRECT, порядок правил | Выберите сервер и проверьте первое совпадение в Connections |

Журналы функции смотрите в Cloud Functions/Cloud Logging, запросы браузера — в DevTools. Не отправляйте сырые URL/пэйлоады в issue. При сборке ZIP большой бинарник требует загрузки через packages-бакет; автоматическая установка зависимостей может занимать время.

## Известные границы

Импорт произвольного Clash YAML — best effort: DNS/TUN, все расширенные proxy-поля и клиентские overrides не гарантированно переживут обратное преобразование в JSON. Предпочтителен JSON для резервной копии. Rule `PROCESS-NAME` зависит от ОС/режима клиента. Базы GEOSITE/GEOIP обслуживает клиент, редактор их не поставляет. Новый starter до активации источников маршрутизирует напрямую. Cloud probes проверяют доступ из облака, а не скорость/маршрут вашего телефона.

Не проверены в этой подготовке: новый живой деплой в отдельном аккаунте, реальные устройства четырёх платформ, все доступные транспорты подписок. CI/локальные тесты подтверждают код, структуру и очищенный starter, но не эти внешние условия. Большой frontend-bundle остаётся известным предупреждением сборки.

## Завершение эксплуатации

Сначала сохраните приватные резервные копии. В своём каталоге удалите Gateway и функцию, затем нужные объекты/версии и бакеты, отзовите ключи и лишние роли аккаунтов. Проверьте оставшиеся логи/версии и расходы в Billing. Бюджет — уведомление, не автоматический выключатель всех ресурсов. Не запускайте удаление ресурсов прежнего владельца и не удаляйте общий каталог с чужими проектами.
